First 30 Days

The minimum version. The full constitution is a manual to look things up in, not a set of rules to follow daily.

Open the notebook. Write one physical step. Start it.

Every day

  1. Date at the next blank line. Never backfill missed days.
  2. RECONNECT: glance at the week + calendar. Anything urgent?
  3. FIRST: one physical action. Do it for 5 min, then continue, change approach or stop.
  4. Log transitions that matter, not every minute.
  5. Stopping? Leave a NEXT: line. That's the whole shutdown.
THU 26 NOV
○ 14:00 Sync (CAL)
FIRST: open analysis notebook; run baseline
11:15 – Baseline reproduced
NEXT: check segment B @36

Marks you need

•Open action. Verb + visible result.
×Done (write over the bullet)
>Moved to a project page: > @42
<Deferred: < CAL or < LATER
○Event (the calendar owns it; this is just a reference)
–Note, observation, decision
!Insight worth coming back to
•Struck through = cancelled

Optional: = feeling. Not needed yet: ₹ spend, * priority. A plain sentence is always fine.

Interrupted? Park & Pivot

One line: where you were + what to do on return.

  → dashboard bug

If it's urgent, handle it first and write the line afterwards.

Capacity modes

FullAll of the above.
LightProtect commitments, FIRST:, NEXT:.
SurvivalOne necessary action. Protect anything time-bound. Nothing else.

Switch freely. No need to label the day.

Fell off? Zero-debt reset

[today] — RESET
Right now: • ________
FIRST: ______________

Start that now. Later: check calendar + work tools for anything urgent, then scan from the last review boundary. Never fill in empty days.

Projects (keep it simple)

  • Only for outcomes that need several sessions.
  • One page per project: outcome, open bullets, a NEXT: line.
  • Indent subtasks. Give a subtask its own page only when it outgrows the parent page.
  • Addresses are page numbers only (@42).
  • Front index page: GPU → 42. That's the directory.
42   CUDA Playground [GPU]
Outcome: run CUDA from mobile browser
× Set up Modal
• Execution backend
    • Capture stderr
• Mobile editor
NEXT: capture stderr

Weekly review · 15 min ALARM

  1. Rescue: scan this week's pages for open •. Move, do, defer or strike each.
  2. Projects: does each one have a NEXT:? Park any you won't touch.
  3. New week: 1–2 lead outcomes + a few real tasks on a small spread.

Low energy? Do step 1 for urgent items only, then pick one lead. Write Reviewed through @38 so you know where to restart.

Set up once, today

  • Daily calendar alarm: "Open notebook → FIRST:"
  • Weekly calendar alarm: "Weekly review · 15 min"
  • Notebook lives where the next transition happens: beside the laptop, or with your keys.
  • Clip on today's page.

For 30 days, don't

  • Edit the constitution. Write – FRICTION: … in the notebook instead.
  • Add apps, trackers, habit rows or sync pipelines.
  • Start experiments before day 15. After that, at most one small one, and only if the core feels easy.
  • Rewrite a page to make it neater.

Day 30 check

  • Did I open the notebook on most days?
  • Does opening it make starting easier?
  • Can I resume a project without rereading days of logs?
  • Did anything important get missed?
  • What came up as FRICTION more than once? Fix only that.
